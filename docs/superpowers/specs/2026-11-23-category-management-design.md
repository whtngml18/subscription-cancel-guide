# 카테고리 관리 — 설계

날짜: 2026-11-23

## 문제
카테고리는 SQL로 넣는 3개(OTT, 음악, 쇼핑 멤버십)뿐이고 관리자 화면에서 늘릴 수 없다. 서비스 추가·수정과 제보 승인에서 맞는 카테고리가 없으면 고를 수 없다.

## 결정
| 항목 | 결정 | 버린 안 |
|---|---|---|
| 만드는 곳 | 관리 페이지 + 폼 안 "+ 새 카테고리" 둘 다 | 한 곳만 |
| 주소(slug) | 관리자가 영문으로 입력, 만든 뒤 고정 | 한글 주소, 자동 번호 |
| 관리 범위 | 추가 · 이름 수정 · 서비스 0개일 때만 삭제 | 표시 순서 지정, 추가만 |
| 빈 카테고리 | 사용자 화면에서 숨김(탭·사이트맵 제외, 주소는 404) | 빈 안내 화면 |
| 기본값 | 6개: OTT(ott), 음악(music), 쇼핑 멤버십(shopping), AI·생산성(ai), 배달·생활(life), 기타(etc) | 3개 |

## 규칙
- 이름: 필수, strip 후 1~30자. 주소: 필수, `^[a-z0-9]+(-[a-z0-9]+)*$`, 30자 이하, 다른 카테고리와 겹치면 "이미 있는 주소예요." (서비스 slug와 같은 형식)
- 이름이 겹치는 것은 막지 않는다(주소가 구분한다).
- 정렬: 지금처럼 id 순.

## 1. 관리 페이지 `/admin/categories`
- 관리자 메뉴(adminHeader)에 "카테고리"를 "가이드 관리"와 "제보 검토" 사이에 둔다.
- 표: 이름, 주소, 서비스 개수, 동작. 동작은 "이름 수정" 링크와, 서비스가 0개일 때만 "삭제" 버튼.
- 위쪽 추가 폼: 이름 + 주소 → POST `/admin/categories`. 성공하면 목록으로 돌아가 "카테고리를 추가했어요." 표시.
- 이름 수정: GET/POST `/admin/categories/{id}/edit`. 주소는 읽기 전용 글자로만 보여 준다.
- 삭제: POST `/admin/categories/{id}/delete`. 서버에서 서비스 개수를 다시 확인하고, 1개 이상이면 지우지 않고 "서비스가 있는 카테고리는 지울 수 없어요."를 보여 준다.

## 2. 폼 안에서 바로 만들기
- `fragments/subscription-fields.html` 카테고리 select 맨 아래에 `<option value="0">+ 새 카테고리</option>`를 둔다. 서비스 폼과 제보 승인 폼이 이 조각을 같이 쓴다.
- 서버: `categoryId`(Long)는 그대로 두고, **값 0은 "새 카테고리"**로 약속한다(`SubscriptionForm.NEW_CATEGORY_ID = 0L`, DB id는 1부터라 겹치지 않음). 폼에 `newCategoryName`, `newCategorySlug`를 더한다.
- 0을 고르면 새 카테고리 이름·주소 칸이 나타난다(JS로 hidden 토글). JS가 없어도 두 칸은 보이고, 0일 때만 쓰인다.
- 검증: 0일 때만 새 카테고리 이름·주소 규칙과 주소 중복을 검사. 오류는 그 칸 아래에 표시하고, 폼은 입력값을 그대로 다시 보여 준다.
- 저장: 서비스 저장(또는 제보 승인)과 같은 트랜잭션에서 카테고리를 먼저 만들고 그 카테고리를 쓴다. 서비스 쪽에서 실패하면 카테고리도 롤백된다.

## 3. 사용자 화면
- 메인 탭: 서비스가 1개 이상인 카테고리만 (`groupedByCategory`가 이미 빈 묶음을 빼는지 확인하고 탭도 같은 기준으로).
- `/category/{slug}`: 카테고리가 없거나 서비스가 0개면 404.
- 사이트맵: 서비스가 1개 이상인 카테고리만.

## 4. 기본값 SQL
- `data-mysql.sql`은 앱이 켜질 때마다 실행된다. 지금은 `INSERT IGNORE`라서 관리자가 지운 기본 카테고리가 다음 시작 때 되살아난다.
- **카테고리 표가 비어 있을 때만** 기본 6개를 넣는다: `INSERT INTO category (name, slug) SELECT ... FROM DUAL WHERE NOT EXISTS (SELECT 1 FROM category)` 형태로 한 문장(6행 UNION ALL).
- 개발용 `data.sql`(H2, 매번 새로 만듦)에는 3개를 더 넣는다. 기존 서비스의 category_id(1~3)는 그대로 유지되도록 뒤에 추가한다.

## 테스트
- 관리 페이지: 추가 성공, 주소 형식 오류, 주소 중복, 이름 수정(주소 불변), 빈 카테고리 삭제, 서비스 있는 카테고리 삭제 거절, 비로그인 접근 차단
- 폼: 서비스 폼에서 새 카테고리로 저장 → 카테고리와 서비스 모두 생성. 새 카테고리 주소 중복 → 둘 다 저장 안 됨, 입력값 유지. 제보 승인에서 새 카테고리로 승인
- 사용자 화면: 빈 카테고리가 메인 탭·사이트맵에 없음, `/category/etc` 404, 서비스를 넣으면 나타남

## 범위 밖
표시 순서 지정, 주소 변경(이전 주소 리디렉션), 카테고리 아이콘·설명, 카테고리 합치기.
