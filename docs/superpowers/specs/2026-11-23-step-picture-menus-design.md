# 단계 그림에 실제 메뉴 이름 채우기 — 설계

날짜: 2026-11-23

## 문제
단계 그림이 휴대폰 틀 + 점 하나뿐이라, 그림만 보고는 어디를 눌러야 할지 따라 할 수 없다.

## 결정
| 항목 | 결정 | 버린 안 |
|---|---|---|
| 방식 | 도식을 실제 메뉴 이름으로 채운다 | 스크린샷, AI 이미지 생성(부정확) |
| 메뉴 출처 | AI는 사용자 글에 나온 이름만 넣는다. 나머지는 관리자가 적는다. 모르는 자리는 회색 줄 | AI가 추측해서 채우기 |
| 그림 모양 | 메뉴 목록 + 누를 줄만 강조 | 나머지 흐리게 + 말풍선, 단계별 가로 이어 그리기 |
| 화면 종류 | 목록 하나 | 대화상자, 탭바 |
| 저장 | `GuideStep.otherMenus` 글자 칸 하나 | 별도 `StepMenu` 테이블 |

## 그림 규칙 (`fragments/steps.html`의 `miniPhone`)
- 휴대폰 위쪽에 `screenName`을 화면 제목으로 보여 준다.
- 목록은 5줄로 고정한다. 강조 줄(`targetLabel`)이 들어갈 자리는 `position`으로 정한다: top-left·top-right=1번째, middle=3번째, bottom=5번째, 값이 없으면 middle. (위치 값 4종은 기존 그대로)
- 나머지 4줄에는 `otherMenus`를 위에서부터 순서대로 넣는다. 강조 줄 자리는 건너뛰고, 메뉴가 모자라면 회색 줄로, 남으면 버린다.
- 강조 줄은 브랜드 색 배경 + 굵은 글씨로 그린다. 색에만 의존하지 않도록 `>` 표시도 붙인다. 회색 줄은 `aria-hidden` 처리한다.
- 그림 전체에 대체 텍스트를 붙인다: "{screenName} 화면에서 {targetLabel}을(를) 누르세요".

## 데이터
- `GuideStep`에 `@Column(length = 300) String otherMenus`(nullable)를 추가한다. 한 줄에 메뉴 하나씩 저장한다.
- `getOtherMenuList()`는 줄 단위로 나누고, trim한 뒤 빈 줄을 빼서 돌려준다.
- 생성자와 `update()`에 매개변수를 추가한다. `GuideStepForm`에는 `@Size(max = 300)`을 단다.
- 기존 행은 null → 회색 줄만 보인다. 개발·운영 모두 ddl-auto가 칸을 추가하므로 SQL 변경은 없다.

## 관리자 단계 폼
- "이 화면에 보이는 다른 메뉴 (한 줄에 하나)" textarea를 추가한다. 안내 문구: "모르면 비워 두세요. 그림에 회색 줄로 나옵니다."

## AI (`FactchatStepParser`, `AiStepsJson`)
- 단계 JSON에 `otherMenus: string[]`를 추가한다.
- 프롬프트 규칙: "사용자 글에 실제로 나온 메뉴 이름만 넣는다. 지어내지 않는다. 없으면 []."
- 응답에 칸이 없거나 null이면 빈 목록으로 받는다(이전 형식과 호환). 각 이름을 50자로 자르고, 합쳐서 300자를 넘지 않게 한다.
- 제보 승인 때 줄바꿈으로 이어 붙여 `otherMenus`에 저장한다.

## 테스트
- `getOtherMenuList` 나누기와 빈 줄 처리
- 줄 배치: position 3종 × 메뉴 0개/2개/6개
- AI JSON 파싱: otherMenus 있음/없음/null
- 폼 300자 초과 검증
- 화면 확인: 375px에서 긴 메뉴 이름이 말줄임으로 나오는지

## 범위 밖
대화상자·탭바 화면, 단계 가로 이어 그리기, 스크린샷 업로드.
