# 화면 전체 개편 설계

- 작성일: 2026-11-21
- 상태: 승인됨 (2026-11-22)
- 구현 계획: 1단계 `docs/superpowers/plans/2026-11-22-ui-redesign-step1.md`
- 관련: 이슈 3개로 나눠 진행 (아래 "작업 순서")

## 1. 왜 바꾸나

사용자 피드백: "화면이 유치하고, 내용이 눈에 들어오지 않는다."

현재 화면에서 확인한 문제:

- 가이드 화면에서 같은 단계가 두 번 나온다 (글 목록 + 큰 휴대폰 그림 목록).
- 휴대폰 그림 하나가 화면을 거의 다 차지하고, 안은 회색 줄뿐이라 스크롤만 길어진다.
- "어디서 해지하는지, 몇 단계인지, 환불이 되는지" 같은 핵심 정보가 아래쪽에 묻혀 있다.
- 홈에는 검색창과 카테고리 상자 3개뿐이라 어떤 서비스가 있는지 보이지 않는다.
- Bootstrap 기본 모양 그대로라 특징이 없고, 글자 크기·굵기 차이가 작아 중요한 내용이 튀지 않는다.
- 없는 주소로 들어가면 개발용 오류 화면(Whitelabel Error Page)이 그대로 나온다.

## 2. 목표와 성공 기준

- 검색으로 들어온 사용자가 가이드 화면 첫 화면에서 "해지하는 곳 · 단계 수 · 난이도 · 주의할 점"을 바로 읽을 수 있다.
- 가이드 화면의 단계는 한 번만 나오고, 휴대폰 화면 너비(375px)에서 단계 하나가 한 화면 안에 들어온다.
- 홈에서 전체 서비스를 아이콘과 함께 한눈에 보고, 카테고리로 거를 수 있다.
- 관리자는 목록에서 각 가이드에 비어 있는 정보를 한눈에 본다.
- 기존 기능(검색, 제보, AI 미리보기, 피드백, 관리자 CRUD·승인, SEO, PWA)은 그대로 동작하고, 기존 테스트가 모두 통과한다.

## 3. 디자인 방향

- 분위기: **정보 사이트·문서 느낌** (사용자 선택). 흰 배경, 진한 회색 글자, 남색 강조색 하나.
- 참고한 곳:
  - Subger (한국어 해지 가이드): 위치 표시(홈 › OTT › 넷플릭스), 제목 아래 한 줄 요약, 정보 칩
  - CancelFreely: "공식 해지 페이지 열기" 큰 버튼, 주의할 점 상자, 난이도
  - JustDeleteMe: 쉬움·보통·어려움 난이도 색 표시 (색 상자 디자인은 제외)
  - GOV.UK 단계 안내: 번호 동그라미를 세로선으로 이은 단계 목록

## 4. 디자인 기본과 공통 화면 틀

- Bootstrap을 빼고 `static/css/site.css` 하나로 바꾼다. 기존 `app.css`, `phone.css`는 합치거나 지운다.
- 색·글자 크기·간격은 `:root` CSS 변수로 정한다.
  - 기본: 배경 `#fff`, 글자 `#1f2328`, 보조 글자 `#59636e`, 선 `#d0d7de`, 강조 `#1f4fa8`
  - 난이도: 쉬움 초록(`#1a7f37` / 배경 `#e7f5ec`), 보통 회색, 어려움 빨강(`#b42318` / 배경 `#fdecea`)
  - 주의 상자: 글자 `#9a3412`, 배경 `#fff6f1`, 테두리 `#f5c2a8`
- 글꼴: Pretendard (jsDelivr CDN), 본문 16px, 줄 간격 1.6.
- 본문 최대 폭: 사용자 화면 720px, 관리자 화면 960px.
- 공통 조각(`fragments/layout.html`): 조각 이름 규칙(head·header·footer 금지)과 인자(`pageHead(title, description, path)` 등)는 유지하고 내용만 바꾼다.
  - 머리글: 사이트 이름, 작은 검색창, "제보하기" 링크
  - 바닥글: 안내 문구
  - 위치 표시(breadcrumb) 조각 추가
- 부품 클래스: 버튼, 칩, 알림 상자, 주의 상자, 폼(오류 표시 포함), 표, 서비스 아이콘, 단계 목록, 작은 휴대폰 도식.
- 서비스 아이콘: 이미지가 있으면 이미지, 없으면 브랜드 색 네모 + 서비스 이름 첫 글자.
- 반응형: 단계의 작은 휴대폰 그림(가로 50px)은 글 오른쪽에 붙고, 400px 미만에서는 글 아래로 내려간다.
- PWA: 서비스 워커가 미리 저장하는 파일 목록을 새 CSS로 바꾼다.

## 5. 사용자 화면

### 홈 `/`
- 제목, 한 줄 소개, 큰 검색창.
- 카테고리 탭: 전체 · OTT · 음악 · 쇼핑 멤버십 (DB의 카테고리 목록으로 만든다).
  - 자바스크립트가 있으면 홈 목록을 바로 거른다.
  - 탭은 `/category/{slug}` 링크이기도 해서 자바스크립트 없이도 동작하고 SEO를 유지한다.
- 카테고리별로 묶은 전체 서비스 목록. 한 줄 = 아이콘 · 이름 · "앱 · 웹 · 3단계 · 약 3분" · 난이도 칩.
- 맨 아래 "찾는 서비스가 없나요? 제보하기 →".

### 카테고리 `/category/{slug}`, 검색 `/search`
- 홈과 같은 목록 줄 모양.
- 검색 결과가 없으면 "'○○' 가이드가 아직 없어요" + 제보 버튼(서비스 이름 미리 채움, 기존 동작 유지).

### 가이드 `/guide/{slug}` (위에서 아래 순서)
1. 위치 표시 (홈 › 카테고리 › 서비스)
2. 아이콘 + 제목 "○○ 해지 방법"
3. 한 줄 요약: 저장된 값으로 자동 생성 (예: "앱이나 웹에서 3단계로 해지할 수 있어요")
4. 칩: 난이도, 해지하는 곳, 단계 수, 예상 시간, 확인일, 출처(관리자 작성/사용자 제보)
5. "공식 해지 페이지 열기 ↗" 버튼 (링크가 있을 때만, 새 탭, `rel="noopener noreferrer"`)
6. 요약 상자: 경로(단계의 화면 이름을 › 로 이은 것), 환불 안내
7. 주의할 점 상자 (있을 때만)
8. 해지 단계: 세로선으로 이은 번호 목록, 단계마다 "화면에서 [버튼]" 제목 + 설명 + 작은 휴대폰 도식. 기존 큰 휴대폰 목록은 없앤다.
9. 피드백: "됐어요 / 달라요" + "N명 중 M명이 됐다고 했어요"
- 비어 있는 정보(해지하는 곳, 주의할 점, 예상 시간 등)는 "아직 확인된 정보가 없어요. 알고 계시면 알려 주세요 →" + 제보 링크로 보여 준다.

### 제보 `/submit`
- 서비스 이름, 해지 방법은 그대로.
- 접었다 펴는 "더 알려 주실 수 있나요? (선택)": 해지하는 곳 체크박스(앱/웹/전화/기타), 주의할 점, 아이콘 이미지 첨부.
- AI 미리보기는 새 단계 블록 모양으로 보여 준다.

### 기타
- 제보 완료: 안내 문구 + "홈으로", "다른 서비스 제보".
- 404·500 오류 화면: `templates/error/404.html`, `error/500.html`. 검색창 + "홈으로".
- 오프라인 화면: 새 디자인으로.

## 6. 데이터와 기능 변경

### Subscription에 추가

| 필드 | 형식 | 규칙 |
|---|---|---|
| `channels` | `Set<CancelChannel>` (APP, WEB, PHONE, OTHER) | DB에는 `"APP,WEB"` 글 한 칸 (AttributeConverter). 목록 조회 때 추가 조회가 없게 하기 위함 |
| `caution` | String | 500자, 비워 둘 수 있음 |
| `difficulty` | enum `Difficulty` (EASY, NORMAL, HARD) | 비워 둘 수 있음 |
| `officialCancelUrl` | String | 500자, `https://` 또는 `http://`로 시작, 비워 둘 수 있음 |
| `estimatedMinutes` | Integer | 1~120, 비워 둘 수 있음 |
| `icon` | `IconImage` (ManyToOne, LAZY) | 비워 둘 수 있음 |

### IconImage (새 엔티티)
- `id`, `data`(byte[]), `contentType`, `updatedAt`.
- 서비스 표에 이미지를 넣지 않고 따로 두는 이유: 목록을 불러올 때 이미지 바이트까지 읽지 않기 위해.
- DB에 저장하므로 배포 서버를 다시 만들어도 사라지지 않는다.
- 업로드 규칙: PNG·JPEG·WebP만, 200KB 이하. 파일 앞부분(매직 바이트)으로 실제 형식을 확인한다. SVG는 스크립트를 담을 수 있어 받지 않는다.
- 내보내기: `GET /icons/{id}` — 서비스에 연결된 아이콘만 공개. `Cache-Control: public, max-age=31536000, immutable`, 주소에 `?v={updatedAt}`를 붙여 바뀌면 새로 받게 한다.
- 승인 전 제보에 첨부된 아이콘은 공개 주소로 보이지 않고, 관리자 전용 주소(`/admin/icons/{id}`)로만 본다.
- multipart 최대 크기 설정(`spring.servlet.multipart.max-file-size`)을 둔다.

### Submission에 추가
- `channels`, `caution`, `icon` (모두 비워 둘 수 있음).

### 관리자 승인
- 기존 "AI 단계 가져오기" 옆에 체크박스 두 개 추가: "해지하는 곳·주의할 점 가져오기", "아이콘 가져오기".
- 새 서비스로 승인: 기본 체크. 기존 서비스로 승인: 기본 해제, 체크하면 기존 값을 바꾼다.
- 해당 정보가 없는 제보에서는 체크박스를 보여 주지 않는다.

### 바꾸지 않는 것
- AI 프롬프트(단계만 나눔), 검색 방식, 피드백 방식, 보안 설정.
- AI로 아이콘을 자동으로 찾는 기능은 다음 이슈로 미룬다.

### DB 반영
- 로컬 H2: 지금처럼 시작할 때마다 새로 만든다. `data.sql` 예시 데이터에 새 칸 값을 채운다.
- 배포 MySQL: `ddl-auto: update`로 새 칸·새 표가 추가된다.

## 7. 관리자 화면

- 공통: 같은 글꼴·색, 업무용 빽빽한 배치, 폭 960px. 메뉴: 가이드 관리, 제보 검토(대기 개수 배지), 사이트 보기, 로그아웃.
- 가이드 목록: 표(아이콘·서비스, 카테고리, 난이도, 단계 수, 빈 정보, 확인일, 수정). "빈 정보"는 비어 있는 항목 이름을 노란 글자로. 검색창과 "+ 새 서비스".
- 서비스 추가·수정 폼: 구역 3개(기본 정보 / 해지 정보 / 확인). 아이콘 업로드와 미리보기. 아래에 단계 목록(작은 휴대폰 포함)과 제보 원문. 틀린 칸은 빨간 테두리 + 오류 문구.
- 단계 추가·수정 폼: 칸은 그대로, 작은 휴대폰 미리보기.
- 제보 검토 목록: 서비스 이름, 제보 시각, 첨부 여부(AI 단계 · 아이콘 · 추가 정보).
- 제보 검토 상세: 2단(왼쪽 사용자가 보낸 내용과 AI 단계 / 오른쪽 승인 폼, 체크박스 3개, 반려). 좁은 화면에서 1단.
- 로그인: 가운데 작은 상자.

## 8. 작업 순서

각 단계는 이슈 → 브랜치 → 코드 → 확인 → 커밋 → PR → 머지이며, 단계마다 사용자 허락을 받는다.

1. **디자인 기본 + 사용자 화면**: `site.css`, 글꼴, 공통 조각, 단계 블록·작은 휴대폰, 홈(아이콘 목록·카테고리 탭)·카테고리·검색·가이드·제보·완료·404/500·오프라인. DB는 바꾸지 않고, 새 칸 자리는 "아직 정보가 없어요"로 둔다. 아이콘은 글자 아이콘만.
2. **새 정보 칸**: Subscription·Submission 필드, IconImage, 업로드 검사, `/icons/{id}`, 승인 가져오기, 관리자 서비스 폼·제보 폼·가이드 요약 연결, `data.sql`.
3. **관리자 화면 새 디자인**: 목록(빈 정보), 서비스 폼 구역, 단계 폼 미리보기, 제보 검토 2단, 로그인.

## 9. 확인 방법

- 자동 테스트
  - 아이콘 파일 검사: PNG·JPEG·WebP 통과, SVG·200KB 초과·확장자만 바꾼 파일 거부
  - `channels` 변환기: 비어 있음 ↔ null, 순서 보존
  - 승인 시 새 칸·아이콘 가져오기 (체크/해제 각각)
  - 승인 전 제보 아이콘이 `/icons/{id}`로 보이지 않음 (404)
  - 없는 주소 → 새 404 화면
  - 기존 테스트 12개 계속 통과
- 화면 확인: 단계마다 앱을 실행해 375px·1280px 스크린샷으로 보고.
- 접근성: 글자 대비(WCAG AA), 키보드 탭 이동, 폼 오류 문구와 입력 칸 연결(`aria-describedby`).
