# 캡처와 글 안내로 단계 그림 자세히 — 설계

- 날짜: 2026-11-24
- 상태: 사용자 검토 대기

## 1. 왜 하는가

단계 그림은 "해지 방법을 더 쉽게 알려 주기" 위해 만들었지만, 제보 글이 짧아 지금은 휴대폰 틀 + 누를 줄 하나뿐이라 있으나 마나 한 그림이 많다.
그림을 자세하게 만들되 **틀린 정보가 들어가지 않는 것**이 가장 중요하다(해지 가이드가 틀리면 결제가 계속 나간다).

## 2. 원칙 (사용자와 합의)

1. AI는 **제보한 사용자의 글이 뼈대**다. 단계 순서와 누를 버튼은 글을 따른다.
2. **해지 화면 캡처는 보강**에만 쓴다: 버튼 위치, 화면 이름, 그 화면의 다른 메뉴.
3. 글에도 캡처에도 없는 내용은 만들지 않는다(AI 일반 지식·추측 금지).
4. 글과 캡처가 다르면 글을 따르고 관리자에게 "캡처와 다름"으로 알린다.
5. AI 결과는 지금처럼 **관리자 승인 뒤에만** 공개된다. "달라요" 피드백은 그대로.
6. 이번에 하지 않는 것: AI가 빠진 정보를 사용자에게 되묻기(제보자가 귀찮음), 캡처를 사이트에 공개하기, 브라우저에서 캡처 가리기 도구, AI 일반 지식으로 메뉴 채우기.

## 3. 나누기

이슈 하나, PR 두 개.

- **1부**: ① Gemini 연결, ③ 프롬프트(글 규칙 + 개인정보 + 조각 조립 구조), ⑥ 글쓰기 안내. 캡처 없이도 바로 효과가 있다.
- **2부**: ② 캡처 받기·안내, ③ 프롬프트의 [캡처 읽기] 조각, ④ 저장·삭제, ⑤ 관리자 화면.

## 4. 설계

### ① AI 연결: Gemini (OpenAI 호환 주소)

학교 factchat은 이번 달 크레딧이 소진됐고(402 insufficient_quota), ChatGPT 구독에는 API가 없다. Google Gemini API 무료 등급의 OpenAI 호환 주소를 쓴다.

| 설정 | 값 |
|---|---|
| `app.ai.base-url` (`AI_BASE_URL`) | 기본 `https://generativelanguage.googleapis.com/v1beta/openai` |
| `app.ai.api-key` | `AI_API_KEY` → `GEMINI_API_KEY` → `FACTCHAT_API_KEY` 순서로 첫 값 |
| `app.ai.model` (`AI_MODEL`) | 이미지 입력을 받는 Gemini Flash 계열. 정확한 이름은 키 발급 뒤 AI Studio에서 확인해 정한다 |
| `app.ai.trailing-slash` | 기본 false. 학교 게이트웨이를 쓸 때만 true(`/chat/completions/`) |

- `FactchatStepParser` → `OpenAiCompatibleStepParser`로 이름 변경. `StepParser` 인터페이스에 이미지 목록을 받는 메서드를 둔다(`parse(serviceName, rawText, images)`, 이미지 없으면 빈 목록).
- 사용자 메시지 content를 문자열 → 배열(`{"type":"text"}` + `{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}`)로 바꾼다. 이미지가 없으면 text 하나.
- 실패(키 없음·오류·한도 초과): 지금처럼 AI 버튼 숨김 또는 "AI 미리보기를 지금 쓸 수 없어요. 글만으로도 제보할 수 있어요." 제보는 항상 된다.
- 키는 Windows 사용자 환경변수에 사용자가 직접 넣는다. 값은 출력하지 않는다.
- Gemini 무료 등급은 보낸 내용이 서비스 개선에 쓰일 수 있다 → ② 안내 문구에 Google Gemini로 보내진다고 적는다(사용자가 약관 직접 확인).

### ② 캡처 받기·안내 (2부)

- 위치: 제보 화면 "해지 방법" 칸 바로 아래(접힌 "더 알려 주실 수 있나요?" 밖). 선택 항목.
- 여러 장 한 번에, **최대 5장**, 올린 순서 = 단계 순서. PNG·JPEG·WebP, 한 장 5MB·요청 전체 25MB(지금 2MB 한도 상향, 넘으면 `UploadLimitAdvice`가 폼으로 되돌림).
- 고른 순서대로 작은 미리보기 + 번호 + ✕ 빼기(스크립트 없으면 기본 파일 칸).
- 서버 검사: 파일 머리와 실제 디코드 확인(`IconValidator` 방식). 통과하면 긴 변 1280px 이하 JPEG로 줄인다.
- 캡처를 바꾸면 AI 미리보기 결과를 지운다(글 수정 때와 같음).
- 폼 오류로 다시 그려지면 고른 파일이 사라진다(브라우저 규칙) → 오류 옆에 "캡처를 다시 골라 주세요".
- 안내 문구:
  > **해지 화면 캡처 (선택, 최대 5장)**
  > 해지하면서 거친 화면을 순서대로 올려 주세요. 그림 안내가 훨씬 정확해져요.
  > - 누른 버튼이 보이는 화면을 올려 주세요. (예: 프로필 → 계정 → 멤버십 해지 → 확인 창)
  > - 휴대폰 화면 전체를 캡처해 주세요. 잘라 내면 버튼 위치를 알기 어려워요.
  > - 해지와 상관없는 화면, 모니터를 사진으로 찍은 화면은 빼 주세요.
  > - 이메일, 이름, 전화번호, 카드 번호는 가리고 올려 주세요. 캡처는 AI 분석을 위해 Google Gemini로 보내지고, 검토가 끝나거나 30일이 지나면 지워져요.

### ③ 프롬프트

조각으로 조립한다: [원칙] + [글에서 뽑기] + ([캡처 읽기], 캡처 1장 이상일 때만) + [개인정보] + [형식] + [예시].

**원칙**
1. 사용자 글이 뼈대. 단계 순서와 target은 글을 따른다.
2. (캡처 있을 때) 캡처는 위치·화면 이름·다른 메뉴 보강에만.
3. 글에도 캡처에도 없는 화면·버튼·메뉴는 만들지 않는다. 기억·추측 금지.
4. (캡처 있을 때) 글과 캡처가 다르면 글을 따르고 note에 다른 점을 짧게.

**글에서 뽑기**
- 한 문장에 동작이 여러 개면 나눈다("프로필 누르고 계정에서 해지" → 3단계).
- 앞 단계에서 누른 버튼 이름은 다음 단계 화면 이름으로 써도 된다.
- 위치 표현: 오른쪽 위/우측 상단 → top-right, 왼쪽 위/좌측 상단 → top-left, 아래/하단/맨 밑/아래 탭 → bottom, 그 밖·없음 → middle.
- 글에 지나가며 나온 메뉴 이름은 그 화면 otherMenus에. 없으면 [].

**캡처 읽기 (2부)**
- 단계마다 맞는 캡처 번호를 image에(없으면 null).
- 위치: 화면을 위·아래 3등분. 위 1/3의 왼쪽 top-left, 오른쪽 top-right, 가운데 1/3 middle, 아래 1/3 bottom.
- otherMenus: target 근처에 보이는 메뉴·버튼 글자를 위에서 아래 순서로 최대 4개, 글자 그대로. 글자 없는 아이콘은 제외.
- 화면 이름: 캡처 맨 위 제목 글자가 있으면 그것.

**개인정보**: 이메일, 이름, 전화번호, 카드 번호, 결제 금액, 주소, 생년월일은 어떤 칸에도 옮기지 않는다.

**형식**: screen·target·메뉴 50자 이하, note 100자 이하, 단계 20개까지, order 1부터, JSON만.

```json
{"service":"서비스 이름","steps":[{"order":1,"screen":"홈","target":"프로필","position":"top-right","otherMenus":["검색"],"image":null,"note":null}]}
```

**예시(글만)**: "앱 오른쪽 위 프로필을 누르고, 구매 및 멤버십에서 멤버십 해지를 눌러요." → 홈/프로필/top-right, 프로필/구매 및 멤버십/middle, 구매 및 멤버십/멤버십 해지/middle.

**서버 검사 (`AiStepsJson`)**: 기존 검사 + `image`는 1~올린 장수가 아니면 null(캡처 0장이면 항상 null), otherMenus 최대 4개(1부는 기존 규칙 유지, 2부에서 4개 제한), note 100자, 이메일·전화번호·카드 번호 모양 글자 처리: otherMenus는 그 메뉴만 빼고, note는 null로, screen·target에 있으면 그 단계를 뺀다. 단계가 하나도 안 남으면 기존 "형식 오류"와 같이 처리.

JSON 형식은 캡처 유무와 관계없이 같다. 1부에서도 `image`·`note` 칸을 받아 두되 항상 null.

### ④ 저장·삭제 (2부)

- 새 엔티티 `SubmissionScreenshot`: id, submission(FK), imageOrder(1~5), data(줄인 JPEG), contentType. 원본은 저장하지 않는다.
- 미리보기 때는 저장하지 않는다. 제출 때 다시 검사·축소해 저장한다.
- 승인·거절 시 같은 트랜잭션에서 그 제보의 캡처를 삭제한다.
- 매일 한 번 30일 지난 대기 제보의 캡처 삭제(`@Scheduled`). 제보 글은 남는다.
- 관리자 전용 `/admin/submissions/{id}/screenshots/{order}`, `Cache-Control: no-store`. 공개 주소 없음.
- 남용: 기존 제보 제한(IP당 1시간 10번)과 AI 미리보기 제한 유지.
- AI 결과(`image`·`note` 포함)는 `Submission.aiStepsJson`에 그대로 저장.

### ⑤ 관리자 화면 (2부)

- 제보 검토 화면: 원문 아래 캡처 썸네일(번호, 누르면 새 탭에서 크게). 없으면 "캡처 없음".
- AI 단계마다 휴대폰 그림 옆에 `image` 번호의 캡처를 나란히. 없으면 흐리게 "캡처 없음".
- note가 있으면 "캡처와 다름 ⚠" + note.
- 상단 안내: "캡처는 승인하거나 거절하면 지워져요. 필요한 메뉴 이름은 승인 전에 옮겨 적으세요."
- 승인해 AI 단계를 가져올 때 `image`·`note`는 버린다. `GuideStep` 구조는 그대로.

### ⑥ 글쓰기 안내 (1부)

제보 화면 "해지 방법" 칸 위에 펼쳐진 안내 상자.

> **이렇게 적어 주시면 그림이 정확해져요**
> 1. 누른 순서대로 적어 주세요. 한 줄에 한 번 누른 것이면 더 좋아요.
> 2. 버튼이 화면 어디쯤 있었는지 적어 주세요. (오른쪽 위, 왼쪽 위, 가운데, 아래쪽)
> 3. 메뉴·버튼 이름은 화면에 보인 그대로 적어 주세요.
> 4. 앱인지 웹사이트인지 알려 주세요.

- 좋은 예 / 아쉬운 예:
  - 좋은 예: "앱에서 오른쪽 위 프로필 사진을 눌러요. / 아래쪽 '계정'을 눌러요. / '멤버십 해지' 빨간 버튼을 누르고 '해지 완료'를 눌러요."
  - 아쉬운 예: "설정에서 해지하면 돼요."
- "예시 넣어 보기" 버튼: 칸이 비어 있을 때만 아래 틀을 채운다.
  ```
  앱 / 웹:
  1. (어디쯤) '(버튼 이름)'을 눌러요.
  2. (어디쯤) '(버튼 이름)'을 눌러요.
  3. '(해지 버튼 이름)'을 누르고 확인해요.
  ```
  틀 그대로(괄호가 남은 채) 제출하면 서버가 "괄호 안을 실제 내용으로 바꿔 주세요." 오류.
- placeholder는 좋은 예로 바꾸고, "10자 이상 1000자 이하" 아래 남은 글자 수(예: 128 / 1000).
- 안내의 위치 표현은 ③ 위치 표현 표와 같은 말을 쓴다.

## 5. 테스트

- 1부: 가짜 서버로 요청 모양(content 배열, 이미지 없으면 text만, 주소 끝 `/` 설정), 키 환경변수 우선순위, 캡처 0장이면 프롬프트에 [캡처 읽기] 없음, `image`가 null로 바뀜, 개인정보 모양 글자 제거, 글쓰기 안내·예시 버튼 표시, 틀 그대로 제출 시 오류. 실제 Gemini로 짧은 글 3개 전후 비교(키 넣은 뒤).
- 2부: 캡처 5장 초과·형식 오류 거절, 축소 후 저장, 순서, 승인·거절 시 삭제, 30일 정리, 비로그인 차단, [캡처 읽기] 포함, image 범위 검사, 검토 화면 표시, 승인 뒤 image·note 미이전.
- 마지막에 앱 실행 후 데스크톱·375px 스크린샷, 확인 뒤 앱 종료.

## 6. 위험과 대응

| 위험 | 대응 |
|---|---|
| Gemini 무료 한도 초과 | 미리보기 횟수 제한, 이미지 축소, 실패해도 제보 가능 |
| AI가 캡처를 잘못 읽음 | 글이 뼈대, note 표시, 관리자 승인 |
| 개인정보 | 안내, AI 규칙 + 서버 필터, 검토 후·30일 뒤 삭제, 관리자 전용 주소 |
| Gemini 모델 이름 변경 | 설정값으로 분리 |
| 학교 factchat 복귀 | 설정만 바꾸면 됨(trailing-slash 포함) |
